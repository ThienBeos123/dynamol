================================================================================
BITOS STRICT API CAPACITY-FAILURE TEST CASES
Focus: STR_INVALID_CAP detection across various capacity constraints
Both Strict APIs (base-10 and base-n) applicable
================================================================================

NOTES:
- All cases have INSUFFICIENT output buffer capacity
- Tests verify proper rejection when capacity is exceeded
- Expected status: STR_INVALID_CAP for all cases
- Sign handling: "-" counts as 1 character toward capacity
- Capacity 0 is valid edge case (nothing fits, including sign)

================================================================================
VERIFICATION NOTES
================================================================================

For all 70 test cases:

EXPECTED BEHAVIOR:
- Status returned: STR_INVALID_CAP
- Output buffer: may be partially filled (implementation-dependent)
- No crash or undefined behavior
- Capacity check occurs BEFORE writing to buffer

CAPACITY CALCULATION:
- Includes sign character (if negative): 1 byte
- Includes all digit characters: variable per base
- No null terminator counted in capacity (user responsibility)

BASE-10 SUITE (A):
- Digit count roughly = ceil(log10(value)) + 1
- Max 926 digits for 2^3072 - 1

BASE-N SUITE (B):
- Binary: ceil(log2(value)) = 3072 bits = 3072 digits max
- Octal: ceil(log8(value)) = ~1024 digits max
- Hex: ceil(log16(value)) = 768 digits max
- Base-64: ceil(log64(value)) = 512 digits max

BOUNDARY TESTING:
- Each case has exact capacity calculated
- Off-by-one tests (capacity - 1) ensure tight detection
- Passing boundary cases (not included) verify correct threshold


================================================================================
NOTES ON STRICT API ONLY
================================================================================

These cases are STRICT API ONLY because:
- Truncative API would silently fill available space (no error)
- Strict API properly rejects insufficient capacity

Do NOT use these cases for Truncative API testing.
For Truncative capacity tests, see separate truncative suite.
