================================================================================
STOBI BASE-64 TRUNCATIVE API EDGE TEST CASES
Focus: Truncation semantics, incomplete input, invalid digits after truncation
Input sizes: 64-512 chars (practical range)
BigInt capacities: 2-16 limbs
Base-64 charset: 0-9, A-Z, a-z, ., /
Prefix format: 0, (with prefix) or none (without prefix)
================================================================================

NOTES ON TRUNCATION SEMANTICS:
- Truncative API keeps low limbs (least-significant digits)
- Status: STR_TRUNC_SUCCESS if overflow detected
- Data is still valid (filled to capacity, remainder ignored)
- Incomplete input (sign-only, no digits) returns STR_INCOMPLETE
- Invalid digits after fill point are ignored (truncation already occurred)
- Invalid digits BEFORE fill point return STR_INVALID_DIGIT

LIMB CAPACITY vs INPUT LENGTH:
- 2 limbs → ~21 chars safe, 22+ chars trigger truncation
- 4 limbs → ~43 chars safe, 44+ chars trigger truncation
- 6 limbs → ~65 chars safe, 66+ chars trigger truncation
- 8 limbs → ~87 chars safe, 88+ chars trigger truncation
- 10 limbs → ~109 chars safe, 110+ chars trigger truncation
- 12 limbs → ~131 chars safe, 132+ chars trigger truncation
- 16 limbs → ~175 chars safe, 176+ chars trigger truncation

KEY TESTING ASPECTS:

2. Incomplete input handling: sign-only, whitespace-only, leading-zero-only
3. Zero normalization: -0 becomes +0
4. Invalid digits AFTER truncation point: ignored (not errors)
5. Invalid digits BEFORE truncation point: error (STR_INVALID_DIGIT)
6. Sign preservation in truncation
7. Null terminator handling (acts as delimiter)
8. Capacity boundary cases (exact fits, off-by-one)
9. Very large inputs (512 chars) with small capacities
10. Negative sign combined with all edge cases

TRUNCATION SEMANTICS VERIFICATION:
- Input overflowing capacity should result in STR_TRUNC_SUCCESS
- Low limbs preserved exactly (implementer must verify via modulo)
- Remainder discarded without error
- Sign always preserved if present
